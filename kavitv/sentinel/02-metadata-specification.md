# Metadata Sentinel — Specification

## Principle

Metadata health is a **first-class dimension**, separate from playback health.
A channel can be technically playable while its EPG, identity, logo, or
schedule is wrong — and the schedule can be perfect while playback is broken.
Never let a green relay check produce a misleading overall green status.
See [04](04-health-model.md).

## 1. M3U channel identity

Source: `kavitv.m3u` (served from the Pages/repo copy; generated by
`export_iptv.py`).

For each of the 3 channels, verify:

- Channel entry exists in the M3U.
- `tvg-id` present and matches the expected XMLTV channel ID.
- `tvg-name` / display name matches the expected channel name
  (KaviTV Horror / KaviTV Experimental / KaviTV Independent).
- Channel number/name/ID are stable vs. the last verified snapshot —
  unexpected renumbering or renaming is a failure, not a cosmetic change.
- Stream URL present and points at the expected relay endpoint
  (`http://10.0.0.98:8100/kavitv/live/<slug>.m3u8`).
- No duplicate `tvg-id` values across entries.

## 2. XMLTV / EPG checks

Source: `kavitv.xml` (XMLTV), generated by `export_iptv.py` from
`library.json` schedule data.

### 2.1 File integrity

- File reachable and parseable as XML; schema-valid (channels + programmes).
- Malformed XMLTV (unparseable, missing required fields) = FAILED, not a
  warning — downstream EPG depends on it.

### 2.2 Channel IDs

- Every `<channel id="...">` in the XMLTV has a matching M3U `tvg-id`
  (M3U ↔ XMLTV mapping complete, both directions).
- No duplicate channel IDs in the XMLTV.
- No XMLTV channel ID without a corresponding M3U entry (orphan guide data).

### 2.3 Programs

- **Current program:** for each channel, exactly one programme where
  start ≤ now < stop.
- **Start/end validity:** start < stop; duration reasonable for the content
  (not zero-length, not absurdly long).
- **Upcoming programs:** at least N hours of future schedule per channel
  (threshold: 24h; alert below).
- **No conflicting times:** no overlapping programmes on the same channel.
- **Staleness:** current program not absurdly stale (>24h old start with no
  transition is suspicious); schedule not far-future only (>7 days with no
  "now" is broken).
- **Transitions:** last program transition occurred approximately when the
  schedule says it should (guards against a frozen schedule that still parses).

### 2.4 Timezone correctness

- All programme times interpreted in America/New_York.
- Verify the "now playing" program actually matches wall-clock now in ET —
  a timezone shift (e.g. UTC treated as local) shows up here as a systematic
  offset on all three channels.

## 3. Emby ↔ KaviTV mapping

Cross-system consistency chain, per channel:

```
M3U entry → XMLTV ID → Relay slug → Emby channel → Playback session
```

Verify:

- Emby Live TV channel number/name/ID matches the expected mapping
  (470348 = Horror, 470349 = Experimental, 470350 = Independent).
- If Emby reports "watching Channel N", the Sentinel can confirm N maps to
  the expected M3U entry, XMLTV ID, name, logo, and current program.
- Channel number changes in Emby are detected and recorded (Emby may
  renumber; the Sentinel tracks the mapping, not a hardcoded number —
  but an *unexpected* change is flagged).

Failure modes: Emby channel number doesn't match M3U order; XMLTV ID mismatch
causes wrong EPG on the right video; tuner re-import creates duplicate
channels.

## 4. Channel logos

For each channel:

- Logo URL exists in M3U (`tvg-logo`) and in the Emby channel config.
- Logo URL resolves: HTTP 200, not 404/500.
- Response is an actual image (`Content-Type: image/*`), not an HTML error page.
- **Correct association:** the Horror logo is on Horror — not swapped, not the
  old shared logo (the 2026-10-05 regression class).
- No unexpected missing logos.

Logo pipeline reference: 3/3 channels verified with correct individual logos
2026-10-05; `export_iptv.py` preserves per-channel logos on refresh; Pages
serves them.

## 5. Freshness tracking

Record and monitor on every run:

| Metric | Expected | Alert |
|--------|----------|-------|
| Channel count | 3 | any decrease → CRITICAL |
| Program count | ~157 | → 0 or >50% drop → CRITICAL; <100 → WARNING |
| Channels with valid logos | 3 | <3 → WARNING |
| Channels with current EPG | 3 | <3 → WARNING |
| M3U refresh timestamp | recent | age >48h → WARNING |
| XMLTV refresh timestamp | recent | age >48h → WARNING; >7d → CRITICAL |
| Last `export_iptv.py` run | recorded | — |
| Age of oldest metadata | — | >7d → CRITICAL |

### Regression detection

The specific failure this exists to catch: **counts collapsing while video
stays healthy.** A bad export that empties the XMLTV does not stop the relay
from serving bytes — Layer 1 stays green while the guide goes blank. The
Sentinel compares current counts against the last verified snapshot and
alerts on sudden drops *independently* of playback state.

## 6. Metadata verdict

Per run, the Metadata Sentinel produces:

- Per-check PASS/FAIL/WARN with evidence (which file, which channel, what was
  found vs. expected).
- Aggregate metadata verdict: PASS / DEGRADED (warn) / FAILED.
- Counts snapshot (channels, programs, logos, EPG age) for trend/digest use.

This verdict feeds the overall health model ([04](04-health-model.md)) as the
"Metadata healthy" dimension — never merged into the video verdict.
